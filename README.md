# Шифрувальний квест

Веб-застосунок для уроків інформатики: 21 завдання, які учень проходить по черзі. Наступне завдання відкривається лише після правильної відповіді.

| № | Розділ | Що робить учень |
|---|---|---|
| 1–4 | Двійкова система | 2 переведення 10 → 2 і 2 переведення 2 → 10 |
| 5–7 | Об’єм зображення | обчислює об’єм у Кбайт (завжди ціле число): за глибиною кольору, за палітрою, а також обернена задача — скільки кольорів |
| 8–21 | Шифри | Цезар, атбаш, квадрат Полібія, Віженер: дешифрування, шифрування, пошук ключа, подвійний шифр |

Відповіді зберігаються й перевіряються **лише на сервері**, тож у коді сторінки їх не підглянути. Регістр, пробіли й провідні нулі у відповіді не важливі.

## Запуск на своєму комп’ютері

Потрібен Node.js 18 або новіший.

```bash
npm install
QUIZ_SECRET=будь-який-довгий-рядок TEACHER_KEY=мій-пароль npm start
```

Відкрийте http://localhost:3000. Сторінка вчителя: http://localhost:3000/teacher

У Windows (PowerShell):

```powershell
$env:QUIZ_SECRET="будь-який-довгий-рядок"; $env:TEACHER_KEY="мій-пароль"; npm start
```

## Змінні середовища

| Змінна | Обов’язкова | Що робить |
|---|---|---|
| `QUIZ_SECRET` | так | Ключ підпису посилання учня на його спробу. Не змінюйте його під час уроку: учні не зможуть продовжити розпочате. |
| `TEACHER_KEY` | так | Пароль до сторінки вчителя `/teacher`. Без неї сторінка вимкнена. |
| `DATABASE_URL` | для хмари — так | Адреса бази PostgreSQL. Якщо задана, прогрес учнів зберігається в базі й не зникає під час перезапусків і оновлень. Без неї — у файлі `data/progress.json`. |
| `PROGRESS_FILE` | ні | Шлях до файла прогресу, якщо база не використовується. |
| `PORT` | ні | Порт; хмарні платформи задають його самі. |
| `LIMIT_PER_ATTEMPT` | ні | Скільки відповідей на хвилину може надіслати один учень (типово 20) — захист від перебору. |

## Сторінка вчителя

Відкрийте `/teacher` і введіть значення `TEACHER_KEY`. Сторінка оновлюється сама кожні 15 секунд і показує **кожного учня**:

- скільки завдань пройдено (смужка прогресу) і **на якому завданні він зараз** (номер, розділ, назва);
- помилки на поточному завданні й загалом, кількість підказок;
- скільки часу учень сидить на поточному завданні, коли востаннє відповідав;
- стан: **Працює**, **Застряг(ла)** (понад 5 хв на одному завданні або 5+ помилок на ньому — такі рядки підсвічені й стоять першими), **Неактивний(а)** (понад 10 хв без дій), **Завершив(ла)**.

Угорі — підсумок (скільки працює, застрягли, завершили) і карта «Де найважче»: скільки помилок зроблено на кожному завданні і скільки учнів зараз на кожному з них.

Інше:
- перемикач **День** показує спроби за обрану дату (типово — найсвіжішу);
- **CSV** — таблиця за день для Excel, зокрема з помилками на кожному завданні;
- **Ключі** — відповіді до всіх завдань;
- ✕ у рядку — видалити спробу (наприклад, тестову).

Якщо учень закриє вкладку чи браузер, то, відкривши квест знову на тому самому пристрої, продовжить з того самого завдання. Якщо він почне заново («Почати спочатку» або інший пристрій), у таблиці з’явиться нова спроба, а попередня залишиться.

Якщо ключ не підходить:
- у журналі (logs) сервісу під час запуску має бути рядок `TEACHER_KEY задано (N символів)` — перевірте, що N збігається з довжиною вашого пароля;
- пробіли й лапки навколо значення сервер відкидає сам, а регістр літер і розкладка клавіатури мають значення.

## Розгортання в хмарі

### Render
1. Завантажте код у репозиторій GitHub.
2. **Створіть базу:** Render → **New → PostgreSQL** → назва, наприклад `cipher-quest-db` → **Create**. Скопіюйте **Internal Database URL**.
3. **Створіть сервіс:** **New → Web Service** → ваш репозиторій. Build command: `npm install`, Start command: `npm start`.
4. У **Environment** додайте `QUIZ_SECRET`, `TEACHER_KEY` і `DATABASE_URL` (вставте скопійовану адресу).

Таблицю в базі сервер створює сам під час першого запуску. Під час старту в журналі має бути рядок `прогрес зберігається: PostgreSQL`.

> Безкоштовна база Render має обмежений строк дії (Render попереджає про це в панелі) — перевірте умови вашого плану. Як альтернативу можна безкоштовно взяти PostgreSQL на [Neon](https://neon.tech) або [Supabase](https://supabase.com) і вставити їхню адресу підключення в `DATABASE_URL`.
> Безкоштовний вебсервіс Render «засинає» без відвідувачів, і перше відкриття після паузи може тривати до хвилини — відкрийте сторінку за кілька хвилин до уроку.

### Railway
**New Project → Deploy from GitHub repo**, потім **+ New → Database → PostgreSQL**. У **Variables** вебсервісу додайте `QUIZ_SECRET`, `TEACHER_KEY` і `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`.

### Будь-який хостинг із Docker (Fly.io, Google Cloud Run, VPS)
```bash
docker build -t cipher-quest .
docker run -p 3000:3000 -e QUIZ_SECRET=… -e TEACHER_KEY=… -e DATABASE_URL=postgres://… cipher-quest
```
Без бази можна змонтувати теку для файла прогресу: `-v $(pwd)/data:/app/data`.

> **Без `DATABASE_URL`** прогрес зберігається у файлі. На безкоштовних хостингах диск очищується під час перезапуску чи оновлення сервісу, і прогрес учнів зникне. Сторінка вчителя в такому разі показує попередження.

## Як змінити завдання

Усі завдання — у файлі `questions.js`. Шифротексти, двійкові записи й об’єми обчислюються автоматично з відкритих даних, тож достатньо змінити відкритий текст і ключ:

```js
C({ title: "Перше повідомлення", cipher: "Цезар",
    ask: "Дешифруйте слово. Шифр Цезаря, ключ k = 3.",
    show: caesar("ШИФР", 3), answer: "ШИФР",
    hint: "Від номера кожної літери відніміть 3…" });
```

Для зображень функція `imageKB()` зупинить запуск сервера, якщо об’єм у Кбайт вийде не цілим, — так у квест не потрапить задача з дробовою відповіддю. Скільки завдань має бути в кожному розділі, задано в `EXPECTED` унизу `questions.js` (зараз 4 + 3 + 14 = 21) — змініть ці числа, якщо додаєте чи прибираєте завдання.

Після змін запустіть `npm test`: тест проходить увесь квест і перевіряє, що кожна відповідь приймається.

## Як це влаштовано

- `server.js` — Express: API `/api/start`, `/api/answer`, `/api/hint`, `/api/resume`, сторінки вчителя.
- `store.js` — сховище прогресу: PostgreSQL (якщо задано `DATABASE_URL`) або JSON-файл.
- `questions.js` — завдання, шифри, перевірка відповідей.
- `public/` — сторінка учня (HTML, CSS, JS без бібліотек).
- Учень отримує підписане посилання на свою спробу (зберігається в браузері), а сам прогрес — етап, помилки на кожному завданні, підказки, час — зберігається на сервері після кожної відповіді. Тож учень не може підмінити свій прогрес, а вчитель бачить його в реальному часі.
- `npm test` проходить квест через API (з файлом, а з `TEST_DATABASE_URL=postgres://…` — і з базою) і перевіряє, що прогрес переживає перезапуск сервера.
