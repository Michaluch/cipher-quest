# Шифрувальний квест

Веб-застосунок для уроків інформатики: 30 завдань, які учень проходить по черзі. Наступне завдання відкривається лише після правильної відповіді.

| № | Розділ | Що робить учень |
|---|---|---|
| 1–8 | Двійкова система | 4 переведення 10 → 2 і 4 переведення 2 → 10 |
| 9–16 | Об’єм зображення | обчислює об’єм у Кбайт (завжди ціле число), зокрема за палітрою, і розв’язує одну обернену задачу |
| 17–30 | Шифри | Цезар, атбаш, квадрат Полібія, Віженер: дешифрування, шифрування, пошук ключа, подвійний шифр |

Відповіді зберігаються й перевіряються **лише на сервері**, тож у коді сторінки їх не підглянути. Регістр, пробіли й провідні нулі у відповіді не важливі.

## Запуск на своєму комп’ютері

Потрібен Node.js 18 або новіший.

```bash
npm install
QUIZ_SECRET=будь-який-довгий-рядок TEACHER_KEY=мій-пароль npm start
```

Відкрийте http://localhost:3000. Сторінка результатів: http://localhost:3000/teacher?key=мій-пароль

У Windows (PowerShell):

```powershell
$env:QUIZ_SECRET="будь-який-довгий-рядок"; $env:TEACHER_KEY="мій-пароль"; npm start
```

## Змінні середовища

| Змінна | Обов’язкова | Що робить |
|---|---|---|
| `QUIZ_SECRET` | так | Ключ підпису прогресу учнів. Без неї після кожного перезапуску сервера незавершені спроби скидаються. |
| `TEACHER_KEY` | так, якщо потрібні результати | Пароль до сторінки `/teacher`. Без неї сторінка результатів вимкнена. |
| `PORT` | ні | Порт; хмарні платформи задають його самі. |
| `RESULTS_FILE` | ні | Шлях до файла результатів (типово `data/results.json`). |
| `LIMIT_PER_ATTEMPT` | ні | Скільки відповідей на хвилину може надіслати один учень (типово 20) — захист від перебору. |

## Сторінки для вчителя

- `/teacher?key=…` — таблиця: учень, коли завершив, час, помилкові спроби, підказки.
- `/teacher.csv?key=…` — те саме в CSV (відкривається в Excel).
- `/teacher/answers?key=…` — ключі до всіх 30 завдань.

## Розгортання в хмарі

### Render (є безкоштовний план)
1. Завантажте папку в репозиторій GitHub.
2. Render → **New → Web Service** → виберіть репозиторій.
3. Build command: `npm install`, Start command: `npm start`.
4. У розділі **Environment** додайте `QUIZ_SECRET` і `TEACHER_KEY`.

### Railway
**New Project → Deploy from GitHub repo**, потім у **Variables** додайте `QUIZ_SECRET` і `TEACHER_KEY`. Команду запуску Railway візьме з `package.json`.

### Будь-який хостинг із Docker (Fly.io, Google Cloud Run, VPS)
```bash
docker build -t cipher-quest .
docker run -p 3000:3000 -e QUIZ_SECRET=… -e TEACHER_KEY=… -v $(pwd)/data:/app/data cipher-quest
```

> **Важливо про результати.** Вони записуються у файл. На безкоштовних планах диск часто очищується під час перезапуску чи оновлення сервісу, тож **завантажуйте CSV одразу після уроку** або підключіть постійний диск (Render: Disks; Railway: Volumes) і вкажіть шлях до нього в `RESULTS_FILE`.
> Безкоштовний сервіс Render «засинає», якщо ним ніхто не користується, і перше відкриття після паузи може тривати до хвилини — відкрийте сторінку за кілька хвилин до уроку.

## Як змінити завдання

Усі завдання — у файлі `questions.js`. Шифротексти, двійкові записи й об’єми обчислюються автоматично з відкритих даних, тож достатньо змінити відкритий текст і ключ:

```js
C({ title: "Перше повідомлення", cipher: "Цезар",
    ask: "Дешифруйте слово. Шифр Цезаря, ключ k = 3.",
    show: caesar("ШИФР", 3), answer: "ШИФР",
    hint: "Від номера кожної літери відніміть 3…" });
```

Для зображень функція `imageKB()` зупинить запуск сервера, якщо об’єм у Кбайт вийде не цілим, — так у квест не потрапить задача з дробовою відповіддю. Кількість завдань має дорівнювати 30 (змініть перевірку внизу `questions.js`, якщо потрібно більше чи менше).

Після змін запустіть `npm test`: тест проходить увесь квест і перевіряє, що кожна відповідь приймається.

## Як це влаштовано

- `server.js` — Express: API `/api/start`, `/api/answer`, `/api/hint`, `/api/resume`, сторінки вчителя.
- `questions.js` — завдання, шифри, перевірка відповідей.
- `public/` — сторінка учня (HTML, CSS, JS без бібліотек).
- Прогрес учня зберігається в підписаному токені в браузері: якщо закрити вкладку, квест продовжиться з того самого місця. Сервер не зберігає стан спроб, тож працює й на кількох екземплярах.
- Обмеження: учень, який знається на інструментах розробника, теоретично може «відкотити» лічильник помилок, підставивши старий токен. Відповідей це не розкриває.
